# 本地私密金库竞品分析与推广指南

调研日期：2026-06-07  
对象：当前项目 `local-vault-chrome-extension`，一个 Manifest V3 Chrome 插件原型。  
核心判断：不要把它包装成“全功能 1Password/Bitwarden 替代品”。现阶段最有胜算的定位是“无需注册、离线优先、本机加密的轻量密码金库”，面向厌恶云同步、只想快速整理账号的人群。

## 1. 当前产品事实

已实现能力：

- Chrome MV3 插件弹窗，权限只包含 `storage` 和 `clipboardWrite`。
- 本地金库：优先 `chrome.storage.local`，调试环境回退 `localStorage`。
- 主密码派生密钥：PBKDF2-HMAC-SHA256，默认 600,000 次迭代。
- 加密算法：AES-GCM 256 位。
- 明文只在解锁后的 React state 中存在；锁定或关闭弹窗后清空当前明文状态。
- 账号字段：网站、用户名、密码、TOTP Base32 密钥。
- 支持搜索、增删改、复制用户名/密码/TOTP、生成 18 位随机密码。
- 支持 JSON/CSV 导入；当前导出为明文 JSON，并已有风险确认提示。
- 有加密、TOTP、导入导出、密码工具、存储适配相关单元测试。

暂未实现或不应宣传的能力：

- 没有跨设备同步、账号体系、云备份、共享、家庭/团队管理。
- 没有自动填充、自动保存、网页内容脚本、移动端 App、Safari/Firefox/Edge 版本。
- 没有 passkey 管理、暗网监控、密码健康评分、泄露检测、附件/安全笔记。
- 没有第三方安全审计、威胁建模报告、商店上架记录。
- 当前明文导出只适合原型和可信环境，不能作为生产级备份方案宣传。

## 2. 目标用户与定位

首选用户：

- 不想注册第三方账号、不想把密码同步到云端的个人用户。
- 开发者、独立创作者、运维/测试人员，用 Chrome 管理少量高频账号。
- 从备忘录、Excel、浏览器散乱保存迁移出来的新手用户。
- 需要一个“本机临时金库/离线备份查看器”的用户，而不是完整家庭/团队协作用户。

不建议优先追的人群：

- 已经重度使用 1Password、Bitwarden、Proton Pass、iCloud Keychain 的用户。
- 企业客户、家庭共享用户、需要多端同步和自动填充的普通大众用户。
- 安全合规要求高、需要审计报告/商业 SLA 的组织。

推荐定位：

> 本地私密金库是一个离线优先的 Chrome 密码金库：不用注册账号，主密码本机加密保存，解锁后快速查找、复制密码和 2FA 验证码。

一句话卖点：

> 密码留在本机，解锁才出现。

差异化原则：

- 不和大厂拼“全平台、自动填充、云同步、企业管理”。
- 用“透明、克制、轻量、本机优先”切入。
- 把功能边界说清楚，比堆“绝对安全”词更能建立信任。

## 4. 竞品要点摘录

以下信息只作为策略依据，价格和功能应在正式发布前再次确认。

- Bitwarden 在 2026 年 1 月公告中说明：个人 Premium 为每年 19.80 美元，Families 为每年 47.88 美元，基础免费计划继续支持无限登录和无限设备。
- 1Password 个人价格页显示：Individual 年付 2.99 美元/月，Families 年付 4.49 美元/月；其个人计划包含生成密码、自动保存/填充、共享、全设备使用、弱密码/泄露提醒。
- Proton Pass 免费计划强调无限登录、无限设备、浏览器/移动/桌面应用、密码生成、10 个邮箱别名、弱/重复密码提醒和 passkey；付费计划增加无限别名、内置 2FA、安全共享、暗网监控、附件和紧急访问。
- NordPass 个人价格页强调免费/付费分层，付费包含多设备访问、Password Health、Data Breach Scanner、文件附件等；家庭计划支持 6 个用户。
- Dashlane 个人页强调 Premium 与 Friends & Family，能力包含无限密码/设备、AI scam protection、安全共享、暗网监控、VPN、2FA、实时钓鱼提醒等。
- LastPass 免费计划限制为 1 种设备类型；Premium/Families 支持多设备、保存和自动填充、家庭 6 个 Premium 账号等。
- LastPass 2022 安全事件公告显示，攻击者复制了包含部分未加密 URL 和加密敏感字段的客户金库备份。这不代表同类产品都不可信，但说明密码管理器的公开信任机制必须包含威胁模型、加密边界、备份策略和事件响应说明。
- KeePassXC 明确主张 free/open source、ad-free、tracker-free、cloud-free，并强调密码不存远端服务器；这是本项目最接近的精神竞品。
- Google Password Manager 明确内置于 Chrome 和 Android，可跨设备登录、密码检查、导入密码；Apple Passwords/iCloud Keychain 可在 Apple 设备间同步密码和 passkey。

## 5. SWOT

Strengths：

- 本地优先、无需注册、权限克制，容易讲清楚。
- 技术实现路径清晰：Web Crypto、PBKDF2、AES-GCM、Chrome storage。
- 体量小，适合做“工具型插件”，上手成本低。
- 已有测试覆盖，适合逐步公开工程透明度。

Weaknesses：

- 当前没有自动填充和自动保存，普通用户会觉得“不够省事”。
- 无跨设备同步，长期主力使用会受限。
- 明文导出是明显安全短板。
- 没有安全审计，不能打高强度安全背书。
- 只有 Chrome 形态，不能覆盖移动端和 Safari 用户。

Opportunities：

- 大厂云同步和账号体系让一部分用户有隐私顾虑。
- KeePassXC 虽强，但对普通浏览器用户偏重；轻量 Chrome 金库有空位。
- 独立开发者、隐私社区愿意尝试透明、可解释的小工具。
- 可以先从“从 Excel/备忘录迁移到本机加密金库”切入，教育成本低。

Threats：

- Google/Apple 内置工具会持续吞掉基础需求。
- Bitwarden/Proton Pass 免费计划很强，功能价值锚定很高。
- 密码管理器天然高信任门槛，任何过度宣传都会反噬。
- Chrome Web Store 上架审核、安全质疑、负面评论都可能影响转化。

## 6. 产品补齐优先级

上线前必须补：

1. 加密备份导出/导入：保留当前明文导出作为高级/调试入口，但默认导出必须是加密文件。
2. 自动锁定：空闲 60 秒、弹窗失焦、浏览器休眠后清空明文 state。
3. 主密码强度提示：创建金库时给出强度反馈，而不是只检查 8 位。
4. 威胁模型文档：明确能防什么、不能防什么，例如恶意扩展、已沦陷系统、键盘记录器无法防。
5. 隐私说明：不采集、不上传、不建账号；若未来加遥测，必须默认关闭或明确 opt-in。
6. Chrome Web Store 页面素材：截图、短描述、权限解释、备份风险 FAQ。

信任建设的详细执行手册见 [`docs/trust-building-playbook.md`](trust-building-playbook.md)，包括隐私政策、安全说明、威胁模型、权限说明、产品内提示、商店页 FAQ、漏洞响应和 30/60/90 天计划。

发布后 1-2 个版本内补：

1. 密码健康：弱密码、重复密码、旧密码提醒。
2. 域名归一和重复导入去重。
3. 只读查看模式：快速打开、复制后自动隐藏。
4. 安全笔记字段：备份码、恢复码、密钥短文本。
5. 导入向导：支持常见导出 CSV 字段映射预览。

中期再考虑：

1. 自动填充和自动保存：需要新增内容脚本和 host 权限，必须同时更新权限解释和安全模型。
2. 可选端到端加密同步：可以从用户自备 WebDAV/本地文件同步开始，而不是自建云账户。
3. 开源与可复现构建：适合建立长期信任。
4. passkey 管理：技术和浏览器能力复杂，等核心密码体验稳定后再做。

## 7. 推广主张

主文案：

> 本地私密金库：离线优先的 Chrome 密码管理器。无需注册账号，用主密码加密保存在本机，解锁后快速查找、复制密码和 2FA 验证码。

三个核心卖点：

- 本机保存：金库数据保存在浏览器本地存储，不需要云账号。
- 主密码加密：使用 Web Crypto、PBKDF2 和 AES-GCM 加密金库。
- 简洁好查：搜索、复制、TOTP、密码生成、JSON/CSV 导入都在一个弹窗里完成。

谨慎版安全声明：

> 本项目采用浏览器 Web Crypto 对本地金库加密，并尽量减少扩展权限。它不能防御已被恶意软件控制的设备、键盘记录器、恶意浏览器扩展或用户主动导出的明文文件。请妥善保管主密码和备份。

不要使用的宣传语：

- “绝对安全”“无法破解”“军工级加密”“比 1Password/Bitwarden 更安全”。
- “零知识云同步”“自动填充”“跨设备同步”“通过安全审计”。
- “忘记主密码也能恢复”：本地加密产品不应承诺服务器恢复。

## 8. 渠道打法

首发渠道：

- Chrome Web Store：作为主转化页，重点做关键词、截图、权限说明。
- GitHub：如果决定开源，放 README、安全模型、构建方法、issue 模板。
- V2EX / 掘金 / 少数派评论区 / 即刻：偏开发者和效率工具用户。
- B 站 / 小红书：用“别再把密码放备忘录/Excel”做低门槛教育内容。
- Product Hunt / Hacker News / Reddit `r/privacy`、`r/opensource`：仅在开源、英文文档和安装体验稳定后投放。

不建议一开始投放：

- 大额搜索广告：密码管理器是信任型品类，冷广告转化会低。
- KOL 硬广：没有安全审计和稳定版本前，容易被质疑。
- 企业销售：当前功能缺少团队、审计、策略、恢复和 SLA。

渠道关键词：

- 中文：本地密码管理器、离线密码管理器、Chrome 密码插件、2FA 验证码、密码金库、私密金库、无需注册密码管理。
- 英文：local password manager, offline password vault, Chrome password vault, no account password manager, TOTP password manager, private password vault.

## 9. Chrome Web Store 页面建议

插件名称：

- 本地私密金库 - 离线密码管理器

短描述：

- 无需注册账号的本地密码金库，用主密码加密保存账号、密码和 2FA 密钥。

长描述结构：

```text
本地私密金库是一个离线优先的 Chrome 密码管理器，适合想把账号从备忘录、Excel 或零散 CSV 迁移到本机加密金库的用户。

主要功能：
- 主密码加密本地金库
- 搜索、添加、编辑、删除账号
- 复制用户名、密码和 2FA 验证码
- 生成强随机密码
- 导入 JSON / CSV 备份

隐私与安全：
- 不需要注册账号
- 不上传金库数据
- 使用浏览器 Web Crypto 加密
- 扩展权限保持克制

请注意：
- 请妥善保管主密码，忘记后无法恢复
- 导出明文备份有风险，请只在可信设备使用
- 本插件不能防御已被恶意软件控制的设备
```

截图顺序：

1. 创建/解锁金库：突出“离线加密保存”。
2. 账号列表和搜索：突出快速查找。
3. 新增账号：展示密码生成和 TOTP 输入。
4. TOTP 复制：展示 30 秒验证码和复制按钮。
5. 导入/导出风险提示：体现透明边界。

权限说明：

- `storage`：在浏览器本地保存加密后的金库。
- `clipboardWrite`：点击复制用户名、密码或验证码时写入剪贴板。

## 11. 90 天执行计划

第 0-14 天：发布前可信度建设

- 补加密备份导出/导入。
- 补自动锁定和主密码强度提示。
- 写 `SECURITY.md`：威胁模型、加密说明、权限说明、漏洞反馈方式。
- 写 `PRIVACY.md`：不采集、不上传、无账号；如未来变化需版本说明。
- 准备 Chrome Web Store 素材和 5 张截图。
- 招募 20-50 个封闭测试用户，重点观察导入、解锁、复制、备份流程。

第 15-30 天：小范围公开

- 上架 Chrome Web Store 或发布可安装包。
- 发布第一篇产品动机文章和安装教程。
- 在 V2EX/掘金/少数派等渠道收集早期反馈。
- 建立反馈表：系统、Chrome 版本、导入来源、失败文件样例、是否需要自动填充。
- 每周发一次 changelog，展示修复速度。

第 31-60 天：扩大验证

- 增加密码健康、重复网站检测、导入去重。
- 做对比页：不是“打败 Bitwarden”，而是“适合不想注册账号的本机轻量场景”。
- 做 2-3 个短视频：创建金库、导入 CSV、复制 2FA。
- 如果开源，补贡献指南和 release 校验值。
- 跟踪商店转化：访问到安装、安装到创建金库、创建金库到添加第一条记录。

第 61-90 天：决定路线

- 如果用户主要要求“方便登录”，评估自动填充版本。
- 如果用户主要要求“跨设备”，评估加密文件同步或自备 WebDAV。
- 如果用户主要来自技术/隐私社区，优先开源、可复现构建、安全文档。
- 如果用户主要来自小白迁移，优先导入向导、备份提醒和恢复教育。

## 12. 指标设计

隐私友好的指标：

- Chrome Web Store 页面访问、安装数、卸载率。
- GitHub star、issue、release 下载。
- 文档页访问量和教程完成反馈。
- 用户主动反馈表，不默认上传金库或行为数据。

如果未来加遥测，必须满足：

- 默认关闭或首次明确同意。
- 只记录匿名事件，不记录网站、用户名、密码、TOTP、导入文件名。
- 公开列出事件清单。

建议观察事件：

- `vault_created`
- `vault_unlocked`
- `credential_added`
- `credentials_imported_count_bucket`
- `encrypted_backup_exported`
- `copy_action_used`
- `totp_used`
- `auto_lock_triggered`

## 13. 商业化建议

短期不建议直接收费。密码管理器的初期瓶颈不是功能收费，而是信任和留存。

更合适的顺序：

1. 免费发布本地核心版。
2. 建立公开安全文档、稳定版本和用户口碑。
3. 如果开源，可加入赞助/捐赠。
4. 未来再把高级能力做成 Pro：加密备份历史、可选同步、自定义字段、安全笔记、自动填充增强、多浏览器支持。

不建议把“本地保存”做成付费门槛，这是产品最核心的信任点。
